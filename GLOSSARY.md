# VicKitchenCabinet

Parametric kitchen-cabinet design: a design is described by a specification, checked against standards, rendered from many angles, and its images can be edited layer by layer.

## Design and specification

**Design**:
A named kitchen layout kept over time as a series of revisions. Identified by a short id.
_Avoid_: project, kitchen file

**Revision**:
One immutable snapshot of a design's specification together with the operation that produced it. Numbered from 1 and only ever appended.
_Avoid_: version, save

**Specification**:
The complete parametric description of a design; the single source of truth from which every geometry, image and export is derived.
_Avoid_: spec file, model, scene description

**Operation**:
A named, validated change applied to a specification to produce the next revision (add, remove, update a module, change common settings, and so on). Applied against a stated base revision.
_Avoid_: edit command, patch

**Room**:
The walls of the kitchen, their lengths and thicknesses, and the openings in them.

**Wall**:
One of the back, right or left walls. The origin of the coordinate system is the inner corner where the back and right walls meet.
_Avoid_: side

**Opening**:
A window or entrance cut into a wall, located by its distance from the corner.

**Common settings**:
Dimensions and materials shared by the whole kitchen (countertop height, base depth, plinth height, handle style, default materials).
_Avoid_: global settings, defaults

## Cabinets and fittings

**Module**:
One cabinet unit placed along a wall at a distance from the corner. Modules are added, removed and resized as a run, and closing a gap moves the neighbours.
_Avoid_: cabinet, unit, box

**Storey**:
The vertical tier a module belongs to: base (lower), upper (wall), loft (above the uppers, up to the ceiling), tall (floor to ceiling) or corner (corner shelf).
_Avoid_: level, floor, tier (the old three.js export field `tier` is now `storey`)

**Front section**:
One horizontal band of a base module's front, stacked top to bottom: an empty gap, a drawer or a door.

**Door**:
The hinged front panel of a module. Its style is flat, framed or glass.
_Avoid_: shutter, leaf

**Handle**:
The pull on a door or drawer: bar, knob, recessed or none.
_Avoid_: pull, knob (as a general term)

**Corner shelf**:
An open shelf module that wraps the inside corner and runs along both the back and right walls.

**Blind corner**:
The part of a corner module that has no door because it is hidden behind the neighbouring run.

**Countertop**:
The slab over the base modules, with its own thickness and front overhang.
_Avoid_: worktop, stone top

**Plinth**:
The recessed strip under the base modules that lifts them off the floor.
_Avoid_: toe kick, kick board (the three.js export field `toeKickHeight` is now `plinthHeight`)

**Appliance**:
A fridge, sink, faucet, cooktop, hood, oven or light placed in or on a module or wall.
_Avoid_: equipment, device

**Molding**:
A trim run generated by rule, either crown (along the top of the cabinets) or base (along the floor). The path is recomputed from the modules on every build, so adding or removing a cabinet moves the molding with it.
_Avoid_: trim, cornice (as separate concepts)

**Molding profile**:
The 2D cross-section of a molding.

## Standards and knowledge

**Knowledge entry**:
A stored standard, rule or material with a code, a text, and where it applies. The set of entries is the knowledge base.
_Avoid_: rule row, reference

**Source type**:
How binding a knowledge entry is: mandatory, standard, recommended, practice or unknown. It decides the severity of a finding.

**Region**:
A group of countries (global, Southeast Asia, East Asia, North America, Europe, Oceania) used to choose which knowledge entries apply.

**Country**:
The ISO two-letter code of the place the kitchen is installed. For each topic, the single most relevant entry for that country is chosen.

**Finding**:
One result of validating a design against the knowledge base, with a severity of error, warning or info and the modules it concerns.
_Avoid_: violation, issue

## Geometry and views

**Scene**:
The set of parts compiled from a specification: the geometry that renders and exports are produced from.

**Part**:
The smallest piece of generated geometry (a door, a side panel, a handle, a molding segment). Its id is built from the owning module and its role, for example `TD1-door-1`.
_Avoid_: mesh, component, item

**View**:
A named camera angle on a design: perspective, overhead, plan, a front view of each wall, and any pinned camera.
_Avoid_: angle, camera (a camera is the placement of a view)

**Render key**:
A fingerprint of the geometry and camera behind an image. Two images with the same render key line up pixel for pixel.

**Control passes**:
The machine-readable images rendered for a view (lines, depth, normal, segmentation, instance, albedo) that guide image generation.

## Image editing

**Layer**:
Something on an image that can be selected and changed: a single part, or a group such as all doors of a module or all parts of one role. Layers are listed per view.

**Mask**:
The pixels of a view covered by the layers being edited.

**Base image**:
The accepted photographic image of a view that further edits start from.
_Avoid_: original, reference photo

**Image job**:
A request to generate or edit the image of one view. Its kind is gen-0 (first photographic image), edit (change materials of layers) or geometry edit (show a changed shape).
_Avoid_: task (a task is one change inside a job)

**Task**:
One change inside an image job: a target layer and the new material or instruction. A job holds up to eight tasks that must not touch the same part.

**Mode**:
How an edit job relates to the design. Quick changes only the image. Design also changes the specification when the image is accepted.

**Backend**:
What actually produces the edited pixels: recolor (no AI), job-package (export for use with an external chat model), or Gemini.

**Strict composite**:
Merging a generated image back so that every pixel outside the mask is exactly the base image.

**Accept**:
Approving a job's result. This is the only moment an image can change the design; accepting writes a new revision when the job asked for a design change.
_Avoid_: apply, approve, commit

**Geometry edit**:
An image job that shows a changed shape (removed or added module, door style, handle style) by re-rendering the same camera before and after and masking the difference.
